# OpenProject Tray

Приложение Windows в системном трее для управления dev-установкой OpenProject в WSL (`bin/dev`). Сам OpenProject, WSL и PostgreSQL должны быть уже настроены.

## Быстрый запуск

1. Запустите `dist\OpenProjectTray-Setup.exe` и установите приложение для текущего пользователя. Права администратора не требуются.
2. При переходе со старой VBS-версии укажите её `settings.json` в установщике. Файл ищется автоматически рядом с исходниками и через существующий ярлык автозагрузки. Уже имеющиеся настройки в папке назначения не перезаписываются.
3. Запускайте ярлык **OpenProject Tray** в меню «Пуск» или на рабочем столе.

Альтернатива без установки: `dist\OpenProjectTray-portable\OpenProjectTray.exe`. Вся portable-папка необходима; EXE не является самораспаковывающимся единственным файлом. Настройки можно скопировать в её `settings.json` перед запуском.

Когда приложение открыто, ярлык и кнопка StreamDock работают одинаково:

| Состояние | Индикатор | Нажатие |
|---|---|---|
| Приложение закрыто (StreamDock) | Чёрный с контрастной обводкой | Открыть только приложение; следующее нажатие управляет OpenProject |
| Остановлен | Серый | Запуск OpenProject |
| Работает | Зелёный | Остановка → `bundle install` → `db:migrate` → запуск |
| Операция выполняется | Жёлтый | Повторное нажатие игнорируется |
| Ошибка | Красный | Повторная попытка после проверки состояния |

Повторный запуск EXE обращается к тому же экземпляру трея. Выход из трея не останавливает сервер; последующее нажатие распознаёт работающий OpenProject и выполняет миграцию с перезапуском.

`OpenProjectTray.exe --background` запускает только контроллер для мониторинга. Автозагрузка использует `--background --startup`: настройка `AutoStartOpenProject` может запускать остановленный сервер, но не перезапускает уже работающий. Подключение плагина не запускает миграцию и не поднимает сервер автоматически.

## Установка плагина из приложения

1. Правый клик по значку трея → **Плагин StreamDock…**.
2. Выберите **родительскую папку plugins**. По умолчанию предлагается `%APPDATA%\HotSpot\StreamDock\plugins`.
3. Нажмите **Установить / обновить**. Приложение создаст собственную папку `com.openproject.tray.sdPlugin`; другие плагины не меняются.
4. Перезапустите StreamDock и перетащите действие **OpenProject** на кнопку.

Пакет входит в приложение, интернет не требуется. Последний успешно использованный путь сохраняется. Если файлы заняты, закройте StreamDock и повторите установку. При неудачном обновлении сохраняется предыдущая версия. Размеры кнопок хранятся в профиле StreamDock и не удаляются при обновлении пакета.

Плагин предназначен для HotSpot StreamDock под Windows. Совместимость с отдельным приложением Elgato Stream Deck не проверена.

### Настройки каждой кнопки

- **Размер логотипа:** 30–100%, по умолчанию 85%.
- **Размер индикатора:** 8–35% стороны кнопки, по умолчанию 20%.
- Шаг — 1%; изменения видны сразу. **Сбросить размеры** возвращает 85% / 20%.
- Логотип центрируется, индикатор закреплён в правом нижнем углу с отступом 4% и контрастной обводкой.
- **Путь к OpenProjectTray.exe:** пустое поле использует путь, записанный при установке плагина. При переносе portable-папки переустановите плагин или укажите новый путь.

Дополнительно прямо в настройках кнопки доступны:

- **Иконка:** классическая, объёмная плитка, минималистичная и анимированная «Орбита» (8 кадров в секунду, цикл 3 секунды).
- **Положение индикатора:** любой из четырёх углов.
- **Свечение индикатора:** 0–100%; у чёрного индикатора свечение выключено.
- **Закругление логотипа:** 0–50%; максимум превращает плитку в круг.
- Предпросмотр оформления; изменения применяются сразу и сохраняются отдельно для каждой кнопки.

Настройки не влияют на значок трея. Плагин опрашивает контроллер раз в секунду; сам трей проверяет внешнее изменение состояния сервера раз в 5–10 секунд. Когда приложение закрыто, индикатор чёрный: автоматического запуска приложения больше нет. Первое нажатие открывает только приложение, даже если OpenProject уже работает; следующее нажатие запускает стек либо выполняет миграцию с перезапуском. Ошибка работающего контроллера отображается красным. Восстановление связи не повторяет команды.

## Меню трея

Доступны **Старт**, **Перезапуск**, **Перезапуск + migrate**, **Стоп**, открытие браузера и терминала, проверка окружения, подсчёт ожидающих миграций, просмотр журналов, настройки и установка плагина. Двойной клик по значку трея открывает браузер.

Стоп завершает только dev-стек; WSL и PostgreSQL остаются запущенными. Рабочие операции выполняются в фоне.

## Настройки и журналы

`settings.json` расположен рядом с EXE и скриптами. Шаблон — `settings.example.json`.

| Ключ | По умолчанию |
|---|---|
| `OpenProjectRoot` | `/opt/openproject` |
| `Distro` | `Debian` |
| `LinuxUser` | `openproject` |
| `Url` | `http://localhost:3000` |
| `StartWithWindows` | `false` |
| `AutoStartOpenProject` | `false` |
| `OpenBrowserOnStart` | `true` |
| `ColdReadyTimeoutSec` / `WarmReadyTimeoutSec` | `180` / `90` |
| `PrepareTimeoutSec` | `300` |
| `WslWakeTimeoutSec` / `WslCommandTimeoutSec` | `60` / `120` |
| `StreamDockPluginsPath` | Автоматически предлагается папка HotSpot |

Журналы:

- Приложение: `logs/tray-activity.log`.
- Ошибки запуска контроллера: `logs/tray-startup-error.log`.
- Плагин: `%LOCALAPPDATA%\OpenProjectTray\streamdock.log`.
- WSL: `$OpenProjectRoot/log/tray-dev.log` и `tray-prepare.log`.

Трей определяет доступность через настроенный TCP-порт; готовность после запуска дополнительно проверяется HTTP-запросом. Это сохраняет существующую модель проверки, а не идентифицирует произвольный процесс на порту.

## Сборка

Windows 10/11, Windows PowerShell 5.1 и .NET Framework 4.x. Используется системный `csc.exe`, сторонние библиотеки и загрузки не нужны.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build\Build-Release.ps1
```

Результат: `dist\OpenProjectTray-Setup.exe` и `dist\OpenProjectTray-portable\` с приложением и пакетом `plugin\com.openproject.tray.sdPlugin`. Перед повторной сборкой закройте запущенную portable-копию. Сборка не включает пользовательские настройки, журналы и посторонние файлы portable-папки в установщик.

Исходники: `src/Launcher.cs` — запуск; `src/Bridge.cs` — локальный Named Pipe с ACL текущего пользователя; `src/Plugin.cs` — WebSocket-плагин; `src/PluginSupport.cs` — изображения и установка пакета; `src/Setup.cs` — установщик. Меню и операции остаются в `OpenProject-Tray*.ps1`.

`Start-Tray.vbs` оставлен только как совместимый переход к собранному EXE; приложение его не использует.

Тихая установка:

```text
OpenProjectTray-Setup.exe /S /DIR=C:\Apps\OpenProjectTray
OpenProjectTray-Setup.exe /S /IMPORT=C:\OldTray\settings.json
Uninstall.exe /uninstall /S
```

Для путей с пробелами заключайте весь аргумент `/DIR=...` или `/IMPORT=...` в кавычки. Удаление через параметры Windows или `Uninstall.exe` сохраняет настройки, журналы, отдельно установленный плагин, WSL и базу данных. Перед обновлением и удалением закройте трей. Старые журналы при переезде в другую папку можно скопировать отдельно.

## Безопасные автоматические проверки

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\Test-Desktop.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\Test-TrayIntegration.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\Test-PluginDialog.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\Test-Setup.ps1
node .\tests\Test-Inspector.js
node .\tests\Test-PluginProtocol.js
```

Проверки используют отдельные папки в `build/obj`, приватные тестовые каналы, подменённые операции WSL и эмулятор StreamDock. Тесты Named Pipe могут требовать обычного запуска вне ограниченной песочницы. Для двух JavaScript-тестов нужен Node.js; приложение и плагин от него не зависят.

Старый `Test-Tray.ps1` — **живая интеграционная проверка**: меняет настройки и запускает/останавливает настоящий стек. Не входит в безопасный набор. Проверку настоящей миграции и физической кнопки выполняйте отдельно в своей среде.
